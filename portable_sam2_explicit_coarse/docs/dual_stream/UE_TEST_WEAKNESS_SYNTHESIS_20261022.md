## 2. 检测与掩码错误分开看

- 固定bbox IoU≥.5最大匹配数优先Hungarian：40376 / 44988 GT有一对一框，4612未配对（10.25%）；其中3532个GT根本没有任何最终框达到.5。
- 已匹配框中，mask IoU≥.75：35120 / 40376；≥.90：17000 / 40376，仍有高质量掩码空间。
- small未匹配框：4551 / 32400；全部未配对GT中small占98.68%。
- 最终DT最多193/图，0/459触及250上限；不是maxDets250截断。只能用最终记录确认现象，不能定位RPN/NMS/score阈值的因果贡献。
- bbox一对一匹配失败不是掩码IoU绝对上限，也不等于纯漏检；框不足/定位/竞争均可能参与。

## 3. UAV支持与候选压缩

以下32图固定均匀索引抽样，未按错误挑样；支持是投影观测代理，不是严格可见性认证。
|区域|原stride2点覆盖|保留锚点覆盖|原点1px邻域覆盖|保留锚点1px邻域覆盖|
|---|---:|---:|---:|---:|
|gt|67.74%|32.11%|97.37%|92.71%|
|boundary2|70.94%|34.35%|96.82%|91.57%|

离散候选压缩显著减少精确落点；1px邻域可恢复较多覆盖，但“附近有特征”不等于精确3D对应。当前B/D只检验已保留锚点局部邻域，不能恢复完全无锚点区。
全459图观测支持/错误分组见support/summary.json；旧float16 geom重建锚点坐标最大实测误差约0.000489px，接近整数边界可能改变栅格化像素，故全量点支持标为近似。32图额外使用原深度重建精确点核对。
全量按实例等权平均：native GT覆盖92.22%，候选格覆盖97.53%，保留锚点1px邻域覆盖约91.16%。这三个数有不同空间支持定义，不可当作三种方法的精度。
基座漏掉的2px内边界前景像素中，native支持覆盖89.81%，保留锚点1px邻域覆盖约87.88%。因此不能把多数边界漏前景简单解释为完全没有UAV观测；这也不证明观测内容已正确对齐或足以区分实例。
按固定native覆盖率组，<.5的1300个已匹配实例native平均IoU差为-0.000849；≥.8的34833个匹配实例为+0.000987。支持质量可能调节收益，但组间差异仍可能混合尺寸/场景，不据此修改本轮门控或阈值。
支持审计采用最大bbox IoU总和再阈值的Hungarian，错误审计先最大化≥.5匹配数；各自固定内部配对，跨报告匹配实例分母不可混用。

## 4. 尺寸指标解释缺口

canonical evaluator将GT area设为bbox宽×高；现有s/m/l是bbox面积按COCO阈值分组，不能称真正mask面积分组。test真实mask-small32400个，bbox-small仅15019个。
已独立将GT area改为mask面积重算分组，整体Mask/bbox AP在val/test数值回放均不变；没有改冻结evaluator，也不覆盖旧产物。这个补算只修正GT面积字段，其他DT/匹配合同沿用原实现。
