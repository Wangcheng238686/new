## 2. 必须修改的项目

### M1：把 P1 的可识别问题收紧成“空间赋值敏感性”

联合置换确实保留原 support 和四维向量集合，但不保留邻接结构、空间频谱、字段与卫星 query/标签的联合分布，也不保持高度与 dx/dy 的导数相容性。经过 RoI 插值后，实际喂入 mixer 的向量集合和 RMS 亦不再守恒。3×3 卷积可仅因输入变得高频、不物理而变差。

因此，correct 优于置换只支持：**该固定模型的输出和性能对字段在原 support 上的空间赋值敏感**。它不能区分正确几何、平滑先验、query 条件相关性、分布外敏感性和注入幅度效应。正确输入更好与精确对齐只是相容，不是认证。

correct−mean 也不能单独“排除图级统计捷径”：mean 仅保留每通道一阶均值，删除方差、直方图和多尺度结构，并改变物理相容性。若 correct 更好，只能说明该均值替代不足以保持表现；若相当，仅说明在本诊断精度内未见局部结构必要性的证据，不能证明网络只用均值。

草案已经披露上述混淆，但第3.5节和决策表仍需使用以上窄表述。不要让“增强内容证据”在汇总中自动升级为“正确空间几何驱动”。“仅 zero 下降”应改为“对字段置零敏感，信息来源仍不可分”，而不是“证明字段依赖较弱”。不显著也不等于等效；不做预先规定的等效检验，就只报告证据不足。

**不要求增加幅度匹配或更多置换种类。** 当前拒绝观察后临时加实验是正确的；代价是明确保留不可识别性，而不是靠 RMS 记录消除它。

### M2：P2 必须核查 native 真正选中的表面，不能混用 RGB 候选

草案写“保留锚点”，但 P1 使用 native512，RGB 候选的每格8点与 native 最近表面不是同一集合。若用 RGB 候选画24个点，即便都正确，也不能验证 native 正信号的实际来源。

应明确：P2 按冻结 native 选择算法在 CPU 重建每个已选目标像素的原始来源射线，携带 view、source UV、源 camera-Z、world XYZ、卫星连续 UV/Z 和排序选择索引；先验证重建 support 与缓存逐值一致，字段经相同 float16 存储后逐值一致，再选点。native 缓存没有保存这些 provenance，不能从高度或 RGB 候选倒推成唯一来源。不能证明来源时标为无法核查。

选点在各 GT 区位内只从该 native 有支持像素抽取；固定点 seed，避免“按确定性顺序第一个”长期偏到左上或图边。GT union/逐实例边界、腐蚀核及图外处理也须固定。核查 height 对应的 selected surface 与 viewcount/dxdy 的字段来源分开描述，不把一条射线验证为四字段全认证。

### M3：8图24点只能叫独立来源视觉抽查，不能叫外部标定认证

原始 RGB/depth/位姿来自同一渲染链；代数回环属于内部一致性。另画原始 RGB 能发现某些明显冲突，但不是独立的像素表面真值。应把标题改成“原始影像对应抽查”，说明“独立”指审查方式，不指外部真值。

4 train +4 val 对排查明显系统错误够用，对测试集密集小建筑和低覆盖失败的代表性不足。预算不需要扩大，但必须报告这8图的密度、真实实例尺寸、支持分布及缺组情况；没有观察到某类场景则明确未覆盖。不要报告能推广到整库的“对应正确率”或将零个明确错误当校准通过。屋顶/立面/遮挡无法区分时必须保留无法判定。

操作上，只有源 RGB 和卫星 RGB 中可独立辨认的同一结构（例如明确屋顶角、相同纹理交界）才给“外观一致”判断，并标记两幅图的独立识别点及其与投影点的距离；不得只用投影点落在 GT 内来判断。既定24点没有可辨认结构时直接记无法判断，不移动到最好看的点，也不为凑一致样例扩充点数。仅凭原深度、位姿和同一投影公式得到的回环仍归内部一致性。

### M4：明确主指标和可重放比较，避免“两个比较”暗含多个检验

主指标指定为 **Mask AP250**；两个主对比做 Bonferroni 97.5% 区间。Boundary、AP75、分组及纠错均为描述性次要结果，不能从中另挑显著值作确认性主张。否则两对比乘多指标不是只有两个检验。

500次下97.5%区间的每侧尾部约6个样本，端点较粗，必须同时给原始点估计、95%区间、97.5%区间及重采样数，不能包装成精密确认。三次置换不是训练重复，图像bootstrap不覆盖空间相关和干预映射随机性，草案对此基本正确。

置换发生在 **RoI 读取前的整幅 native fields**，不是每个 RoI 独立洗牌；支持、query、检测框、score、mask paste 均不变。保存每图的映射指纹、固定图ID派生算法和旧 records 的校验。各条件都对 GT/框/类别/score 做逐图一致断言。

8图日志回放只检验包装器实现；若复用旧 correct 全量 records，须再核验459张的 checkpoint、源文件、GT、图像顺序/ID和推理合同完全一致。重放不一致则 correct 重跑，不能混用旧结果。

## 3. 资源和实施顺序

建议最小顺序：CPU 来源封存/扰动断言 → P2 固定8图来源重建与抽查 → 有明确系统性错误则暂停 P1 并提交证据；否则空闲 GPU 跑 P1 → 等原有矩阵最终汇总。这样避免先用六轮完整推理分析已知错误缓存。

六条件最多2754图推理，不训练，且绝不抢占当前矩阵，成本可以接受。若 correct 可严格复用就只需五条件。三次置换可反映干预映射波动，但不能支持很强随机性结论；不应因第一次结果好坏增减种子。

RMS 必须累计全部真实调用的平方和/元素数，另报告各图比值和不支持比例。旧最后分块 stats 不能直接替代它。即使对齐了全局 RMS，方向、局部幅度和频谱仍可能变，所以本轮仅记录 RMS 的选择是保守的。

## 4. 对用户最终意图的覆盖范围

| 用户真正需要知道的问题 | 本计划能否回答 |
|---|---|
| 固定 native 模型是否响应字段及其空间赋值 | 可以，限定该checkpoint及这些干预 |
| 有无明显、可复现的原始对应冲突 | 可以发现一部分；未发现不能认证整库 |
| 正确几何而非幅度、频谱或分布外变化是否造成收益 | 不能唯一识别 |
| 接收端混合坐标语义是否限制收益及损失多少 | 不能；本计划不改入口 |
| UAV 相对纯卫星是否有可重复净收益 | 不能新增证明；需要当前矩阵内容控制、训练重复及独立区域 |
| 是否应继续堆 RGB 模块 | 可帮助收窄表述；不能单凭 P1 推翻或选定结构 |

**审核建议：先落实 M1–M4，再实施有限诊断；保留当前 S²DB 固定矩阵。** 待全部主臂/内容控制、来源冻结审计和离线机制证据完成，最多收敛一个候选，做预定独立训练种子与新区域验证。若只剩 depth 的弱正信号，最小深度方案符合原目标；无需为了双 RGB 流形式增加复杂度。若证据仍不足，允许明确“尚未判定”，不要把本轮 OOD 依赖诊断变成选择新架构的许可证。
