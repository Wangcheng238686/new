# UAV源画面对应可行性探针

2026-10-16。CPU读取已有RGB/真实camera-Z、相机和冻结预测诊断；无模型forward、训练、fit、标签修改。协议和6病例名单在RGBD计算前冻结，失败/成功各组按字典序选择、排除跨组重复global ID，没有按画面好看程度换病例。

## 判定

**有继续做局部对应/身份消费探针的空间，但尚未达到推荐实现模型或训练的证据门槛。** 4个固定失败例都不是完全没有源画面投影支持，多个UAV画面可见屋顶层级、立面和相邻体量。然而这些线索是否帮助判断正确的物理建筑归属、是否超越卫星已有线索，当前未被证明。

尤其不能把真实深度投影落入卫星GT当作UAV实例真值。卫星没有深度、UAV没有ID，故本探针无法正确判定卫星视角可见性；同一屋顶投影区域可以收进立面、被遮挡或另一层表面。没有拿地平面假深度代替。

## 位置阴性与4m尺度

固定将两卫星区域水平+32px（越界则整对-32px），相机/depth不变。支持集合随位置变化，但一些view正确/平移支持Jaccard很高，最高0.949（931目标B yaw288）。32px位移不是保证无重叠的异栋阴性；大目标本身有重叠，立面投影还可让不同高度落入相邻卫星区。因此当前结果不能说明‘读到屋顶’就读到了正确的目标特异信息。

按所有screen支持点的真实世界XY量化4m格，两目标分别占格83–499，共同格仅9–20。此粗代理没有显示普遍严重4m平面混格；但它没有模拟生产可见性竞争、候选选择/质量权重、特征平均或特征别名，不能因此排除生产BEV信息丢失，也不能声称未池化一定更好。全部病例详数见summary.json。

## 几何验收

使用生产cameras.py函数（版本2合同，world厘米→米），真实EXR红通道camera-Z厘米→米，未混用ray长度。30view深度metadata位置与相机位置误差0m，FOV误差最大9.28e-7度；像素→世界→同相机 roundtrip最大1.07e-11px。它们是内部/metadata一致性，不证明RGB与深度外部真实对应绝无问题。

跨view固定16px采样格，双方3x3深度变化<1m，11525个样本中7726个残差≤2m，3799个在目标深度后方>2m，前方>2m为0。后方可为真实遮挡，不能直接叫深度错配。931/928遮挡比例尤其高（65.3%/58.5%）；采样是整幅图，不能当目标级可见性量。

## 对下一步的约束

1. 507可作后续冻结特异性/身份消费探针的优先病例，保留其他失败和成功对照；不能据此批准训练。
2. 继续局部源读取探针时，必须同时报告候选/目标可用支持数、上下文来源、遮挡与无支持回退；不把固定5view数当有效证据数。
3. 需要证明读取来自正确目标及上下文、并能区分整栋与局部候选，而非任何邻近屋顶；当前平移阴性只完成位置敏感性的弱检查。
4. 不把现有标签当物理身份真值。无法在未核定标签下验证的部分应保持未知，不能用更多拟合或oracle筛选把未知变成收益结论。
