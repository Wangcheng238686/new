# UAV RGB内容干预：完整开发子集验证

日期2026-10-15。关联EXP-0006/0007；后续于[完整验证审计](UE_DEV_SUBSET_AUDIT_20261015.md)。本轮不训练、不更新权重、不修改生产融合。

## 结论

**当前双流确实对与目标几何配对的UAV RGB敏感，主要表现于mask路径；仍未证明这些RGB提供了超过单流的额外有效信息。**

保持目标深度派生几何全部不变，只替换UAV五视角RGB，两套供体都使完整segm AP下降约3.4–3.5个百分点，bbox AP几乎不变；共同框mask IoU同样下降。不能继续把“模型基本不读RGB”作为主要解释。但这种替换制造RGB-D不一致，也可能破坏外观统计或训练适应，因此不能把下降幅度认作UAV净贡献。

## 范围与协议

当前冻结开发子集153验证图、4496次建筑出现、237栋唯一建筑；不是正在生产的完整开发集或独立test。固定dual E72 strict EMA、eval/inference_mode，无optimizer。代码基于clean `311d055e400ee13cedceb044799ae25e15860569`，源脚本SHA256见运行manifest。

[运行前预注册原文](probes/results_20261015/RGB_CONTENT_PREREGISTRATION.md)固定三臂、指标、选模、bootstrap及判据；[独立审核](../reviews/UE_RGB_CONTENT_20261015.md)保留全文。

- correct_replay：从原文件重新读取同一RGB，验证干预接口sham。
- donor_a / donor_b：保留五视角yaw顺序、RGB通道和像素尺度，替换完整RGB组；供体分别seed1701/1702。
- 每套153个不重复供体，两个映射对每一目标供体不同；跨映射供体集合重叠38个，不是306个独立供体。
- 供体和目标已知建筑ID无交集、manifest footprint矩形不交、原点距离≥1500m，实际最小1508.78/1512.96m。已知ID并不枚举所有UAV可见物体，不能声称绝对无共同可见建筑。
- 验证区域集中，部分目标在val内部没有满足距离约束的供体，所以运行前固定使用同一manifest的train图RGB。供体可能在训练中被看过，不将供体深度、相机或标签输入模型。
- 目标卫星及标签、相机/深度派生候选、参考点、高度、置信、覆盖、投影等全部payload不变，只有`rgb`改变。

## 预注册落判与证据边界

- 稳定配对RGB敏感性门：两映射segm AP差≥.005且各探索性95%区间下界>0，**通过**。
- 固定框mask敏感性门：两映射三框协议IoU差均≥.005，**通过**。
- 弱敏感性门：两映射AP及全部共同框IoU差绝对值均≤.002，**未通过**。

这些是运行前固定的工程诊断门，不是模型净贡献门或统计显著性宣称线。

本轮比zero/BEV shift更具体：非RGB几何固定后仍有差异，说明RGB相关输入确实影响mask。但不能区分目标语义、一般外观分布、RGB-D物理失配和训练先验；两套供体仅降低单一供体选择的偶然性。不要将本轮3.4pp与之前zero约7.5pp直接相减来分摊贡献，干预不同且模型非线性。

独立训练单流segm AP仍为.583000，正确双流仅.584958，GT共同框下单流甚至略高。因此，**依赖配对RGB与获得超过单流的有效互补信息尚未闭环**。

## 下一步方向（尚未执行）

本轮不支持把“不读取RGB”作为主要解释，也不支持仅凭依赖性就宣布融合成功。主要待区分：

1. UAV对当前目标提供的信息与卫星冗余，模型学会依赖但任务不需要它；
2. 有互补信息，但BEV聚合、任务无关表示或注入方式未将它保留为净收益；
3. 额外分支改变训练适应，使正确配对只能补偿自身引入的代价。

下一项更有判别力的证据是匹配训练对照：正常配对RGB双流／训练期间打乱RGB对应的双流，与已有独立单流共同比较；同通用预训练初始化、相同预算、相同深度几何，禁止UE单流热启动。这是区分配对内容训练价值的对照，依然需要注明RGB-D失配。当前用户要求先验证再讨论，本轮不自动拉新训练，也不据此改CVT或融合结构。
