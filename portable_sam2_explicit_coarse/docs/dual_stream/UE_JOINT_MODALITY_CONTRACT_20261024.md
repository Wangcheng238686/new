# 联合训练的模态角色、成本与验收合同

## 用户要求与状态

最终联合模型必须实际消费UAV RGB、UAV深度图和相机内外参，各有明确作用，避免为了凑模态新增无效大分支。下面是工程/证据约束，不宣称所有独立输入收益均已证明。最终卫星与UAV均从共同基础预训练初始化训练；E73冻结探针及裁剪权重只作机制/工程核定，不是最终任务热启动。

## 单条证据链，避免重复分支

1. **RGB外观**：五视角共享源编码器，读取连续源坐标处的外观token，归一化后供目标坐标交互使用。当前证据只支持P0消费；不保留未使用的深层计算。
2. **真实camera-Z深度**：原始深度经内参反投影到源相机三维，再经外参到卫星相机投影，确定真实内容应被放到哪个目标格，并产生观测支持/几何属性。不是仅把深度文件路径写入manifest。离线缓存属于深度消费，必须保存源文件SHA和投影生成合同，消融时重建缓存。
3. **内参K**：定义源像素对应的三维射线和卫星成像投影；不强制增加单独K编码网络。
4. **外参T**：将源三维点变换到卫星坐标，保留视角身份/目标位置关系；不增加可被忽略的pose支路。
5. **内部交互**：目标格U与卫星S局部交互并回写S′，继续后续Hiera/检测/掩码。只保持一个入口，既有直接实例监督及U高分辨率路径暂保留作配对参考。显式四字段CNN是否进入正式版须由内容/成本证据决定，不因深度必须被使用而强制保留。

上述设计使RGB携带内容、深度提供实测三维对应、K/T执行坐标变换。几何对应本身已有明确用途，不要求再叠加大深度backbone、深度重建头或多层BEV来证明深度存在。输入接线和任务收益分别验收，不能保证每项去除都一定跌分。

## 已落实的计算削减

`rsprompter/uav/rgb_p0_encoder.py::RGBP0Encoder`从现有共享源编码器提取patch embedding、位置嵌入、Hiera blocks0/1和P0的lateral卷积，不注册未被消费的后续stage。构造时检查stage_ends与P0无top-down依赖，保留原状态与相同源格点。

`scripts/analysis/ue_rgb_p0_efficiency_gate_20261024.py`实际读取seed44 RGB internal正确E10，首个固定val样本五视角验证：40个状态张量与完整源逐值相同；FP32与AMP共10份P0输出逐值相同；全部归一化连续候选读取逐值相同；相同起始RNG的训练前向逐值相同，10个有效LoRA梯度在3次完整源重放噪声的2倍范围内（最低1e-7）。最初要求CUDA反向逐位相同失败，patch LoRA A差1.43e-6，对应完整源自身重放噪声1.67e-6；没有把非逐位一致伪报成逐位一致。

完整源参数70168240，P0源404240；P0有效可训练参数25648保留。按现有几何/交互/头259893、RGB投影8224和RGB融合27840求和，候选紧凑UAV分支约700197参数。这个算术数不含原卫星，也不是已部署正式模型的实测总参数。

同卡FP32五视角源编码（预热2轮，测5轮）中位104.025ms→15.205ms；额外peak allocated143.5→87MiB，两者共同常驻参数仍在显存中。它是单样本共享设备源编码观察，不是整模型延迟/AP证据。产物`ue_instance_interaction_20261024/p0_efficiency_gate/`，已核验源码/实际CP身份。

裁掉后层会去掉未使用LoRA dropout的RNG消费，所以完整训练随机流不逐位一致。新联合运行器须独立固定其随机合同/初始化，不能宣称直接复用旧探针的训练轨迹或续训状态。该模块尚未替换任何冻结14臂代码。

后续全val门`scripts/analysis/ue_rgb_p0_full_val_gate_20261024.py`已实际完成459图×5视角FP32 P0逐值比较，并将接口临时替换为紧凑源，逐图比较全部RGB读取/融合后的U128及support，均逐值相同；adapter状态、CP、冻结源身份保持。产物`p0_full_val_gate/complete.json`已前台核对459个唯一ID。这覆盖交互接收的UAV输入，不是最终检测输出或整个训练轨迹一致性；随后共同基础初始化的正式联合前向、非空AdamW/AMP/五RNG恢复、同批溢出重算及最大250推理实例门已完成；已开始四臂100epoch训练。这些工程门仍不是最终AP证据。

## 标定数据的已确认限制

`scripts/analysis/ue_camera_variation_audit_20261024.py`核对3060份cameras.json及三split计数。每个视角的K在每split精确唯一；UAV到卫星相对位姿按6位小数也各只有一个值，跨split一致。世界位置会随采样点变化，但不是新的相对rig。

因此：

- 跨图替换K/相对pose，或以训练均值替换，会近似/完全等于原值，不能作为“去除相机信息”的有效实验。
- 在固定rig数据上，网络或缓存可以隐式记住标定；不能仅凭当前数据证明逐样本读取K/T优于把正确rig写成常量。
- K/T是实际几何算子的必要参数，但不应强行包装成独立具有样本语义增量的模态。当前证据可支持几何对齐机制及标定敏感性；跨rig泛化需后续不同rig数据验证，不以错误标定跌分替代。
- 全量相机SHA及范围见`camera_variation_audit/complete.json`，此审查只描述标定变化，不按test参数选模型。

## 消融如何避免空挂和泄漏

|要检验的作用|主要匹配训练对照|不允许的替代说法|
|---|---|---|
|RGB真实外观|同结构、初始化、预算的常量RGB训练；真实深度与标定保留|只用固定权重RGB错配跌分证明训练收益|
|实测深度建立对应|以仅由train确定的无实测深度几何先验重建全部候选、支持和属性，再匹配训练；如固定参考表面，明确偏差与覆盖变化|仅把height/dx/dy置常量，仍保留真实深度候选，却称无深度|
|几何数值编码|真实四字段对匹配常量字段，保留相同实际对应；有必要时单独隔离字段组|把四字段整体效果归给高度或高度差单项|
|物理对齐算子|固定rig下对比预先定义的非物理/学习对齐方案，匹配读取范围与预算并公开覆盖差；标定扰动另作敏感性诊断|固定rig跨图错配无效，或乱标定破坏输入后声称证明独立模态价值|
|内部交互|同内容/结构head与internal比较，再结合常量内容差；最终联合训练需同预算纯SAT基线|只比较整模型对旧SAT，不排除新增容量/训练机会|

无实测深度的首个先验已在任何相应AP/新训练前固定为**穿过renderer sampling origin的水平面**（relative_z_m=0），使用camera射线与该平面相交，非实测地面估计。`geometry_inputs.py`提供无文件I/O的投影/候选/native转换；相同函数输入实测深度时，在预定val首/中/末3图逐值复现旧index/geom/FP64 anchor/fields/support。参考平面构建期间禁止所有文件open的门通过，全部无效深度返回空候选及空支持。平面对照重新生成所有产物，不保留真实source_uv、support、视角数、排序或高度。

`scripts/probes/ue_reference_plane_cache_20261024.py`以两CPU worker生成独立`/data/wangcheng/cache/ue_v1_reference_plane_20261024`全3060缓存；源码/split/camera SHA绑定，运行时审计钩子禁止EXR与三套实测缓存读取，可按同一合同恢复。全3060参考缓存已构建完成，并由输入审计重核全部实际npz/camera SHA（约10.42GB）；相同通用SAM2/新任务头初始化的纯SAT、完整RGB-D、常量RGB、参考平面四臂100epoch匹配训练已启动，E3已有完整验证点值；尚未完成全预算与最终测试，学习对齐对照未实现且不是本轮固定矩阵的一项。相机扰动保留错误输入属于OOD敏感性，与重新训练去信息对照分开。
