# 2026-10-22 GPU 共租调度修订

用户明确要求：有显存时立即共租启动，不再等待独占空卡。本修订只改变资源调度，保留模型、数据、初始化、随机种子、优化器、训练预算、E10选权和评价合同。

## 实际入口

`scripts/probes/ue_probe_coresident_owner.py`接管S²DB矩阵和六条件Native固定权重诊断。原两个调度owner停止，已启动的训练子进程保留；旧v1控制训练和测试owner继续运行。原冻结调度源码不修改。

调度依据每卡实际显存，并为新进程启动和训练激活峰值补足工作预算：训练6500 MiB、评价3500 MiB、Native工程门4500 MiB，每卡余量2048 MiB。旧测试owner可能在GPU1启动的评价额外预留3500 MiB；该预算允许其他任务共租，不再独占该卡。

物理空闲显存不全等于可分配显存：刚启动的训练尚未达到工作峰值，调度按其预算与实际分配差值补足。容量释放后自动启动后续就绪任务；有科学先决条件的第二阶段仍遵守原依赖。
