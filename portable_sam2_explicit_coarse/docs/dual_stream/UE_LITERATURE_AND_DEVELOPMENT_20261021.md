# 现有数据证据约束下的文献与开发方向（2026-10-21）

## 1. 判断

有充分的相邻任务证据支持继续验证“跨视角RGB-D帮助目标视角分割”，但尚不能据此认定我们的五视角UAV一定能提高强卫星基座的单类别实例AP。本轮核实的论文没有直接覆盖我们这套输入、标签和评价设定；这也不是不存在同题工作的穷尽性声明。

建议实现一个几何锚定的局部源特征适配器：保留表面与视角，依据深度投影找到候选，再由卫星查询挑选证据，只注入一个SAM高分辨率入口。CVT提供查询思想，DeepViewAgg提供观测选择依据，Multi-View SAM提供少视角深度与SAM解码互补的证据，HQ-SAM提示细节需要进入合适的消费路径。这是综合推导的工程假设，不是复现某篇已证明在本数据上有效的架构。

## 3. 核心文献：任务支持与工程借鉴分开

### 3.1 Multi-View SAM（WACV 2024）

**Joint Depth Prediction and Semantic Segmentation with Multi-View SAM**

- 原文：https://arxiv.org/html/2311.00134v1
- 3–5视角构建MVS深度，深度再作为dense prompt帮助SAM式语义解码。ScanNet表中微调SAM配其解码器为59.0 mIoU，完整模型62.5，GT深度版本63.4；冻结SAM编码器配其可训练解码器47.2，加入GT深度52.4。
- **支持：** 少量视角、深度信息和SAM表征可以形成分割互补，不必先求全场景完整重建。
- **限制：** 室内语义分割；完整模型同时改变多视角处理和联合学习；并非冻结我们的整个解码器后添加UAV即可复现其收益。
- **借鉴：** 将深度相关信息送到解码消费路径。我们已有深度，不复制MVS深度预测任务。

### 3.2 DeepViewAgg（CVPR 2022）

**Learning Multi-View Aggregation In the Wild for Large-Scale 3D Semantic Segmentation**

- 原文：https://arxiv.org/html/2204.07548v2
- 作者代码：https://github.com/drprojects/DeepViewAgg
- 在点与图像的对应上，根据距离、方向、遮挡等观测条件学习视角选择与聚合；目标是3D语义分割。
- **支持：** 多视角观测质量不均，简单平均和单纯堆叠可能稀释有效信息；源图像特征的分辨率也影响结果。
- **重要区别：** 其注意力分数依赖观测条件。作者报告尝试基于特征的self-attention增加显存却无明显收益，不能把它引用成“卫星Q/K/V必然最优”的证据。
- **借鉴：** 保留候选的来源与观测条件，避免太早把不同表面压成同一个BEV向量。先采用有效性掩码和恒等退化；只有发现全是坏候选仍被强制聚合的问题后，再考虑最小的拒绝机制，不照搬整套点云网络与门控。

### 3.3 CVT（CVPR 2022）

**Cross-view Transformers for real-time Map-view Semantic Segmentation**

- 原文：https://arxiv.org/html/2205.02833v1
- 利用相机感知的位置编码和图像特征，以地图查询聚合多摄像头信息。
- **支持：** 几何位置与外观联合决定跨视角映射，查询式构建目标视角特征是可行技术路线。
- **限制：** 其任务是车辆/道路等地图视角语义预测，并非卫星建筑实例轮廓；原始CVT并不等同于本方案的深度约束局部查询。
- **借鉴：** 保留query读取源证据的思想。既然已有深度，不要求网络重新学习全部投影，也不强制独立构建一个覆盖固定世界范围的BEV。

### 3.4 HQ-SAM（NeurIPS 2023）

**Segment Anything in High Quality**

- 原文：https://arxiv.org/html/2306.01567v1
- 作者代码：https://github.com/SysCV/sam-hq
- 保留预训练SAM权重，训练额外HQ token及相关模块，结合早期/最终ViT与解码特征改善细节。
- **支持：** 细节信息需要进入掩码生成路径，冻结已有大模型、训练少量新增参数也有成功先例。
- **限制：** 它有新的预测token和精细mask训练集，不是“冻结所有解码参数只相加一个特征”已经得到验证，也没有UAV输入。
- **借鉴：** 用它解释入口选择，不再新增一个与本项目UDPR重叠的尾部修正头。

### 3.5 SG-BEV（CVPR 2024）与CRFFNet（Information Fusion，卷127，2026）

- SG-BEV：https://arxiv.org/abs/2404.02638
- CRFFNet出版方摘要/预览：https://www.sciencedirect.com/science/article/abs/pii/S1566253525008577
- 两者用街景信息增益俯视建筑**属性**分割。SG-BEV用深度和卫星footprint引导BEV特征再分布；CRFFNet使用显式BEV几何先验，减少对深度与复杂相机输入的要求，并使用地图数据。
- **支持：** 跨视角补充能改善卫星坐标下的建筑理解；对齐与特征分布是实际问题。
- **限制：** 功能/楼层属性的互补性不能直接等同于单类实例边界互补性。向建筑内部扩散立面特征适合属性预测，却不能作为提升轮廓定位的直接依据。CRFFNet本轮只核实出版方摘要和预览，未取得全文，未审计其具体实现。

### 3.6 S²DB-Net（ISPRS JPRS，卷240，2026年10月）

**Urban sidewalk detection via a cross-view joint segmentation method using satellite and street-view imagery**

- 出版方摘要/预览：https://www.sciencedirect.com/science/article/pii/S0924271626003503
- 通过隐式透视转换、特征采样聚合与辅助监督，利用街景补充卫星图中被遮挡的人行道。摘要报告三个数据集相对单视角方法的IoU提升9.18、6.47、8.62个百分点。
- **支持：** 比建筑属性更接近我们需要的“跨视角补充目标形状/空间分布”，不只是分类语义变化。
- **限制：** 仍是人行道语义IoU，不是建筑实例AP；其标签是否覆盖卫星不可见部分、辅助监督的具体条件需全文核对，不能直接搬到我们仅卫星GT的条件下。本轮核实摘要和预览，未取得全文。

### 3.7 Aerial Lifting（CVPR 2024）

**Aerial Lifting: Neural Urban Semantic and Building Instance Lifting from Aerial Imagery**

- 原文摘要：https://arxiv.org/abs/2403.11812
- 作者代码：https://github.com/zyqz97/Aerial_lifting
- 将多视角2D预测提升到NeRF三维场，结合重建深度先验、尺度融合和跨视角实例分组，改善城市建筑实例理解。
- **支持：** 多视角几何确实能服务建筑实例任务，是回应“三维信息是否有用”的直接相邻证据。
- **限制：** 它仍专门处理实例对应/分组；重建几何不自动附带实例身份。其场景建模与训练流程远重于当前适配器，不能按五图数据直接套用或将其3D结果当卫星Mask AP收益。

## 4. 建议的最小开发链

```text
五视角UAV RGB → 共享编码器（开放LoRA）→ 一个源特征尺度
                       ↓ 携带视角及轻量几何元信息
深度+标定 → 可见表面点 → 投影到实际卫星图坐标 → 局部候选
                                                   ↑
冻结卫星分支 → 一个SAM高分辨率特征 → Query → 一层局部聚合
                                                   ↓
                       有效支持掩码 × 零贡献初始化的残差适配器
                                                   ↓
                       原SAM/CSPM/UDPR → 原卫星实例mask监督
```

1. **几何明确位置，学习负责选择。** 深度首先用于对应；候选可包含屋顶、立面和地面，不把墙一律删除，也不把墙投到屋顶内部。目标仍是卫星标注定义的可见mask。源深度形成的最近表面不等于完整目标视角可见性认证。
2. **不要在细节进入解码器前过早合并。** 一个源特征尺度，保留同卫星邻域内多个表面候选。源尺度选择需结合真实分辨率/显存核定；若尝试stride4，应明确是待实施选项，而非已有证据结论。不能对跨屋顶/立面边缘的深度做无条件均值下采样。
3. **一个入口。** 首版不同时接FPN、BEV和第二个掩码头。先打通全图坐标、特征像素中心、缩放/padding以及roi_local裁样的严格合同；不能把全图坐标直接当RoI局部坐标。
4. **轻量几何属性。** 如果用相对高度、源距离、投影偏移/方向，仅选少量属性并固定规范化；不直接拼cm级绝对世界坐标进归一化特征。没有卫星深度时不虚构双向遮挡检验。
5. **保留恒等路径。** 无候选位置增量为0，关闭新增分支精确复现基座。最终损失应经过冻结SAM/UDPR向新增模块传梯度，不能对中间特征detach或把冻结模块包进no_grad。零残差系数会使首步上游梯度为0；应确认系数本身可学习且随后梯度恢复，不能同时把所有残差末层初始化成无法打开的零路径。
6. **先沿用已有损失。** 卫星mask监督可以训练源分支；没有UAV/BEV标签也不妨碍端到端反传。已有监督能否驱动该入口仍待验证，不新增虚构UAV标签、实例ID一致性或边界loss。冻结检测参数且不改变其特征输入时，bbox输出应保持一致。

这条路线保留CVT的跨视角查询思想，但不要求独立BEV。开发重点是保持真实测得的三维表面与源外观证据，并把它们送入实际生成掩码的路径。

## 5. 最短验证顺序与证据解释

### 阶段A：基座完成与接口验证

沿用EXP-0017的新数据单卫星流程，按val Mask AP选权重，正式test按既定流程执行。随后冻结该基座，不使用旧E66/E72。只做必要的投影叠图/坐标核定、关闭分支复现、一次反传检查，不再为压缩BEV训练一批离线读出头。

### 阶段B：一个真实下游适配器

先跑固定训练预算的开发筛查，以last比较减少尖峰选择。实际进入正式方法对比时，各可训练方法均按**validation Mask AP**选同一个checkpoint，再报告其bbox/Mask/Boundary三项，不改正在运行的基座选权规则。

最小需要区分：冻结基座；真实UAV适配器；同结构同预算、保留正确几何但将源外观置常量的适配器。第三者并非“什么信息都没有”：它保留深度/相机及卫星query，作用是区分真实外观带来的增量。若其也涨，应进一步区分几何贡献与新增适配容量，不能直接宣布是UAV RGB收益。

固定检查点的zero/错配只作为依赖性诊断，不替代对冻结基座的净收益比较，也不把输入分布外崩溃当作证明。RGB错配保持几何时还产生RGB-D不一致，报告时披露。

### 阶段C：评价与继续条件

- 主指标：COCO Mask AP@[.50:.95]、maxDets=250；max_per_img同为250。AP75作为定位质量伴随指标，不能单独保证细边界收益。
- 补充：Boundary AP预先固定2%图像对角线边界带，1%作为严格伴随设置；所有方法同实现同参数，不按结果挑半径。算法定义参考 https://arxiv.org/abs/2103.16562 及作者 https://github.com/bowenc0221/boundary-iou-api 。
- 首版不改检测路径，因此不以bbox提升为准入要求；若bbox改变，先查是否违背冻结/输入不变合同。
- 看总体AP以及有/无UAV支持区域的错误分布，区分局部收益、错误表面副作用和无效外观；探索性分层不能代替总体结果。
- 小幅提升需考虑种子波动和图像/空间相关性；不能把旧+.14pp量级无不确定性地称为成功。新test不用于调局部半径、源尺度或loss。
- 若仅Boundary AP稳定改善，结论应收窄为轮廓改善；若Mask AP也稳定提高，再论证实例分割整体收益。不要为了“只要某指标更高”持续改变任务或选权规则。
