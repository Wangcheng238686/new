# UE 数据集内外参与投影核验报告

**日期**: 2026-09-19 · **执行**: 独立端到端核验（不依赖训练代码） · **脚本**: 全部内嵌于本报告可复现
**数据**: `/data1/wangcheng/dataset/ue_coco_with_uav`（原生 512 契约）· 8 场景（train 4 / val 4）× 5 视角

## 结论（先行）

**数据集内外参正确，UAV↔卫星双向投影成立。** GT 建筑足迹从卫星图按数据集契约映射到世界坐标、
再经外参投影到 5 个 UAV 视角后，与 UAV 图像中真实建筑轮廓的中位对齐误差为 **2.4 px（UAV 512 图上，
约 0.84 m 地面距离）**，随机放置基线为 29 px。逐视角、逐场景均一致。此前扰动探针（旋转 90°/180°/270°
外参预测无变化）反映的是融合门未开启，**不是几何错误**。

## 1. 数据契约与元数据

`camera_params.json`（`extrinsics_version: 2`）自述约定：

| 字段 | 值 |
|---|---|
| transform | `world_to_camera`（W2C） |
| vector_convention | column |
| camera_axes | `x_right, y_down, z_forward`（pinhole） |
| world_axes | **Unreal 左手系**: `x_forward, y_right, z_up` |
| world_units | **cm** |
| image_origin | top-left, `u_right, v_down` |

- **内参**：5 视角共享同一 K = [[787.91, 0, 256], [0, 787.91, 256], [0, 0, 1]]（512² 图，f≈788 px）。
- **R 正交性**：每视角 ‖RᵀR−I‖∞ = 0（精确正交）；**det(R) = −1**——左手世界系到右手相机系的
  轴手性转换导致的反射，属预期，非数据错误。代码用 4×4 齐次逆矩阵处理即自洽。
- **相机位姿**（C = −R⁻¹t，场景 002080）：水平距离精确 **300 m 环**，方位角精确 **0°/72°/144°/−144°/−72°**，
  高度 335–483 m（俯仰 48–58°）。`-R⁻¹t` 解释下光轴全部**精确指向场景中心**（偏角 0.0°）——
  这是"环形盘旋朝内看"的采集设计，元数据内部自洽性极强。

## 2. 卫星↔世界映射契约

数据集代码（`ue_dual_stream_dataset.py` / `dual_stream.py`）使用：

```
world_x = −(v_sat/512 − 0.5) × 360 m      world_y = (u_sat/512 − 0.5) × 360 m      (z = 0)
```

**实例**（场景 002080，scene_center = (−217500, −117500) cm）：

|---|---|
| (0, 512) 左下角 | (−180, −180) |

| (512, 0) 右上角 | (+180, +180) |
| (512, 512) 右下角 | (−180, +180) |

## 4. 量化对齐统计（决定性检验）

方法：GT 多边形投影到 UAV 图后，测其顶点到 UAV 边缘图（Canny+距离变换）的中位距离；
仅统计 ≥80% 顶点入画的多边形，剔除出画伪影。

**逐视角**（002080，22 个 GT 多边形）：

| 视角 | 中位误差 | p25–p75 | 有效多边形 |
|---|---|---|---|
| v0 | 6.0 px | 2.8–13.9 | 19 |
| v1 | 2.6 px | 1.9–9.0 | 14 |
| v2 | 6.0 px | 3.3–8.8 | 21 |
| v3 | 6.6 px | 3.4–18.1 | 13 |
| v4 | 8.3 px | 5.5–20.1 | 7 |
| **全部** | **6.0 px** | — | 74 |

**逐场景**（每场景 5 视角聚合）：

| 场景 | 中位误差 | n |
|---|---|---|
| train/002080 | 6.0 px | 74 |
| train/002081 | 3.3 px | 151 |
| train/002100 | 1.9 px | 91 |
| train/002150 | 2.4 px | 85 |
| val/002002 | 1.8 px | 25 |
| val/002003 | 2.0 px | 36 |
| val/002010 | 2.3 px | 118 |
| val/002040 | 3.7 px | 149 |

**8 场景汇总：中位数 2.4 px，最大 6.0 px；89% 的投影多边形在 20 px 内。**
随机放置基线 29 px——对齐信号高出随机一个量级，不可能由巧合产生。

屋顶视差检查：把 GT 抬高 0–50 m 重投影，**h=0 最优**——GT 确为 z=0 地面足迹，
与标注生成方式一致；UAV 斜视下屋顶/立面像素相对足迹的偏移（v2 叠加图上可见约数十 px 的
上移）是真实的三维视差，不是标定误差。

## 5. 曾出现并排除的假阳性

- **边缘方向 90° 误差**：直接比较卫星重投影图与 UAV 图的 Sobel 主方向得 ~90° 中位差。
  定位后确认是**统计伪影**：画面被长条形阴影边界主导（卫星阴影 92.5°，UAV 阴影 2.5°），
  且重投影边缘中阴影占比更高。以 GT 轮廓为准的结构检验推翻了该信号——建筑轮廓精确咬合。
- **反投影路径**：UAV 像素→K⁻¹→射线→z=0 平面交点→卫星像素的逆变换与正向投影自洽
  （同一契约式，无独立信息）。

## 7. 对后续工作的含义

1. **BEV 融合的几何前提成立**：`GeometrySparseBEV` 的地面网格契约、覆盖（±180 m）与
   朝向均与数据一致；r2/r3 的 parity 应归因于融合机制/优化动力学（门不开），而非几何。
2. **允许立即回到原始数据集**继续机制改进（prompt-token 注入、非零门初始化等），
   无需怀疑输入侧。
3. 若未来在 UE 中渲染真实云层，本文的 GT 投影脚本可直接复用为遮挡前后的一致性审计。
