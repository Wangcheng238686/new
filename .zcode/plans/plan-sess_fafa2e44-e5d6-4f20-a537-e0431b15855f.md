# iSAID 数据集构建 + 训练管线接入计划

**用户决策**：patch 采用官方标准 800×800 / overlap 200；15 类多分类训练；构建+接入后只做冒烟测试，不启动正式训练。

## 现状盘点（已完成探查）

- **DOTA 原图**：`/data1/wangcheng/dataset/DOTA/{train,val}/images/*.zip` 未解压（train 3 个 zip ≈1411 张，val 1 个 zip ≈458 张），磁盘剩余 2.1T，充足
- **iSAID 标注 JSON**：`/data1/wangcheng/dataset/iSAID/{train,val}/Annotations/iSAID_{train,val}.json`，**多边形完整**（train 1411 图 / 354,789 标注，val 458 图 / 116,649 标注，15 类，无空 segmentation）
- **官方 instance_id PNG**：齐全（train 1411 / val 458），可用于交叉验证
- devkit 官方 `preprocess.py` 依赖老版 detectron/cityscapesScripts/scipy.misc，不采用；自行编写转换脚本（多边形已在 JSON 中，无需从 PNG 提取）
- 代码侧：类别数仅由 config 的 `bbox_head.num_classes` 决定（mask 分支 class-agnostic）；`WHUCocoInstanceDataset` 已预留 `single_class=False + category_mapping` 多类路径；验证评估器 `build_coco_gt_and_dt`（train_rsprompter_fusion.py:82-177）硬编码单类 category_id=1，需多类化

## Phase A：提取 DOTA 原图

1. 检查 zip 内部路径结构后解压，**按 iSAID JSON 的 file_name 清单过滤**，落位到 `/data1/wangcheng/dataset/iSAID/{train,val}/images/*.png`（只保留 JSON 引用的 P####.png，DOTA zip 中的多余文件不引入）
2. 校验：train 1411 / val 458 张，文件名与 JSON 一一对应

## Phase B：构建 800×800 patch 数据集（核心）

3. 新建 `portable_sam2_explicit_coarse/scripts/build_isaid_patches.py`（参照 `resplit_ue_coco.py` 的风格）：
   - 切图逻辑镜像 devkit `split.py`：滑窗 stride=600（800-200），越界回缩对齐边缘；任一边 ≤800 的图整图保留；跳过官方已知损坏的 P1527/P1530（与 devkit 行为一致）
   - 标注裁剪：每条标注的多边形栅格化为实例 mask → 按窗口裁剪 → 面积 < min_area（默认 25px²，可调）的碎片丢弃 → 其余重新编码为 COCO 多边形（跨边界实例保留为单条标注、多 ring），bbox/area 重算
   - 输出：`/data1/wangcheng/dataset/iSAID/isaid_patches_800/{train,val}/images/*.png` + `instances_isaid_{train,val}.json`（含 width/height、15 类官方 categories；train/val 均保留全部 patch，空 patch 无标注——与官方一致，数据集类已正确处理空标注）
   - 工程性：`--workers` 多进程、断点续跑（已存在文件跳过）、`--dry-run`、结束后输出统计（图数/标注数/每类实例数）
4. **交叉验证 QC**：随机抽取 ~20 个 patch，将"我们裁剪的标注栅格化"与"官方 `*_instance_id_RGB.png` 同窗口裁剪"对比：实例数一致性 + 前景（全实例并集）IoU，输出报告；IoU 一致率 ≥95% 视为通过

## Phase C：接入训练管线

5. `data/loader.py`：`create_train_loader` 新增 `dataset_format == "isaid_coco"` 分支，构建 `WHUCocoInstanceDataset`（复用现类）传 `single_class=False, enable_category_mapping=True, category_mapping={1..15 → 0..14}`，train/val 各自的 ann/img 路径参数 + 环境变量覆盖（`ISAID_TRAIN_ANN_FILE` 等，沿用 WHU 模式）
6. `train/train_rsprompter_fusion.py`：新增 `--use-isaid-coco` flag；调用点选择 dataset_format 并传 iSAID 路径；运行快照（~line 1971）记录数据集与 single_class 状态
7. 新配置 `configs/isaid_baseplus_explicit_coarse.py`：`_base_` 继承 `whu1024_baseplus_explicit_coarse.py`，仅覆盖 `model.roi_head.bbox_head.num_classes = 15`（模型输入仍为 1024，800 patch 由数据集类 resize，与 SAM2 编码器一致）
8. 评估器多类化：`build_coco_gt_and_dt` 改为按 `label+1` 写 category_id（单类 WHU：label 0→1 行为不变，完全向后兼容），categories 列表按数据集注入（iSAID 15 类 / WHU 保持 "building"）；打通 `run_validation` 调用链

## Phase D：冒烟验证（GPU 2 空闲）

9. 小比例子集（如 `--train-subset-ratio 0.02 --val-subset-ratio 0.05`）单卡跑 ~50 iter：确认前向/反向/损失正常
10. 强制跑一轮验证：确认 15 类 COCO bbox/segm mAP 输出正常（含逐类结果），冒烟日志留存 `logs/` 下
11. **不启动正式训练**（等用户后续指令；WHU 任务仍在 GPU 0/1 上运行，不受影响）

- `scripts/build_isaid_patches.py`（含 QC 报告）
- 代码改动：`data/loader.py`、`train/train_rsprompter_fusion.py`、新 config；WHU 既有路径行为完全不变
- 冒烟测试日志

预计耗时：解压 ~15 分钟，切图构建约 1–2 小时（多进程），代码改动与冒烟约 1 小时内。
