## 主要观察

1. 最稳定的异常是**图边只露出极少像素的建筑实例**，而不是普通的完整小建筑。
   例如 `3f9ba1e21684a769` 是 1 px 的图边可见片段；
   `2c5b033466d0b892` 是窄边 ≤2 px、面积 84 px 的图边细条。它们可能确实来自
   建筑，但在当前 512² 图像中无法可靠辨认成一个可检测实例，应区分“真实可见
   像素”与“可评估建筑实例”。
2. **不能按触边删除。** `c874af72f86d1a5f` 等大面积触边屋顶仍有清晰的建筑
   形状，属于当前 visible-surface 契约的正常截断实例。
3. **不能按不连通或低 bbox 填充率拆分。** 例如
   `19064360d2c1ae7c` 的同一 local/global ID 覆盖两个分开的屋顶块，元数据
   对应一个 `BPP_Bldg_Hero_Mid_SFA_Triangle_A01` 锚点、3 个 related actors。
   这可能是同一建筑复合体，也可能是 producer 的过度分组；仅凭连通域无法
   判定。另一些分离/稀疏实例来自裁边或遮挡。
4. 普通对照中可见大量屋顶轮廓与 RGB 相符，当前数据**不是整体标签崩坏**。
   但原 producer 的像素级 `clean` 只修补碎屑，不能替代实例本体语义审查。

## 建议的 v3 清洗路线

### A. 区分三种不同问题，不用单一“删 mask”操作

- **确证错误像素/ID：** 背景漏入、错归属、孤立渲染伪影，经 RGB + 原始 EXR +
  `instances.json`/邻近场景交叉核实后作局部修正，记录逐像素 diff 和依据。
  禁止全图开闭运算、轮廓平滑或自动补齐矩形屋顶。
- **真实但不可评估的极薄图边实例：** 优先采用 `IGNORE`，不称为错标，也不
  作为训练正例或 AP 分母；训练损失及 COCO 评估都必须对其正确忽略，避免
  仅删 GT 后把真实建筑预测计为 FP。首个可测试候选规则为
  `touch_border AND (mask_area_512 <16 OR min_bbox_side_512 <=2)`，现有 train/val
  命中数为 569/44。此数值是**待双审冻结的候选门**，不是事后按 AP 优化的阈值。
  不触边的小实例继续逐例复核，不能用此规则一刀切。
- **一 ID 多片/多栋：** 以物理建筑 ontology 与 UE actor/mesh 关联决定。若确为
  同一建筑复合体，保留多连通域；若为多个独立建筑，必须在全部受影响场景中
  一致拆分 global ID 与 local ID，重建实例 mask/bbox，并重审 v2 空间/物体隔离。
  不能按 connected component 自动生成新实例。

### B. 冻结前的最低审查门

1. 先完成 R1 的 A 表 113 例、B 盲审 23 例及冲突裁决；对于 `IGNORE` 候选，
   特别核对是否存在清晰可识别的完整小楼被误排除。
2. 在 train/val 全量应用**同一个已冻结规则**，保存不可变的 v3 label manifest、
   源/派生 PNG 哈希、逐实例 `KEEP/FIX/IGNORE/DROP/UNCERTAIN` 决策和修改统计。
   `UNCERTAIN` 不得静默当背景；尚无可靠依据时维持旧标签并单列遥测。
3. 重算实例数、面积分布、global ID 映射、train/val/test 隔离，以及 B0 reader
   前向样本数；抽查修改前后的 RGB+ID overlay。test 在规则冻结后按同一算法
   一次性处理，不用 test 反向调规则。
4. 任何 v3 AP 要由 v3 数据上的新 B0 重训给出；不得与 v2 的 0.7952 val AP
   直接比较为模型提升。最终报告同时列有效 GT 数、被忽略数、小/中/大面积 AP、
   bbox/segm AP，防止“删除难例”制造虚高。

**关键结论：** 先处理图边不可评估实例与确证错 ID，再解决 producer 的物理建筑
分组争议。普通触边大建筑和合法多片屋顶必须保留；全局面积阈值、连通域拆分、
形态学平滑都不适合作为自动清洗规则。
