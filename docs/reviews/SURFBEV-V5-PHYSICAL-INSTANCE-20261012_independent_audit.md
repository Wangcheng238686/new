# SURFBEV-V5 物理建筑实例清洗：独立只读审计归档

审计者为独立子代理，未编辑脚本、标签或审计对象。范围：R2–R6B 冻结诊断、M2/M3 候选物化；不审模型 AP，不将数据探针当作模型增益证据。

## 诊断链

- R2：36/36 非连通候选已输出，几何 sham 平均重叠 0.205、correct 0.890；预注册主门 **FAIL**，因为已知正例 `170002` 的第二块仅由一场支持，按原 `≥2` 景门被漏检。不得据此物化标签。
- 独立追踪 `170002`：孤立块约 1,088 个 1m 栅格，全部落在其他场景 global `161009` 的占据区域；该位置 51 场可见中 50 场为 `161009`、仅一场误标 `170002`，原始 PNG 已有错误。这是单景 ID 串号，不是稳定的“170002 覆盖两栋”。
- R3：794 个 train/val 场、40,745 个可见实例中，形状筛查列出 489 个相连风险观测/95 个 global，并列出 20 个孤立世界组件。风险库存不是物理楼栋真值，也不能证明未列入者干净。
- R4：20 个孤立组件中 19 个的中心点跨场景指向别的已有 global；这些目标在来源场景的原 `instances.json` 均缺席，所以只改 PNG 会破坏元数据契约。`1874325323` 的 R4 无纠错票是**无留出参考场景的空判定**，不是新的稳定双栋证据。
- R5：19 个候选在排除来源景后的目标多景占据**并集**上原始重叠均为 1.0；独立逐景复算证实非自引用，但并集掩盖低值，不能直接批量改标。
- R6/R6B：同 split、排除来源景、逐格投票及约 3m 邻域实现可复核。26 个来源场景组件为 25 PASS/1 HOLD；按“同一纠错关系所有来源场景通过”，实际为 **18/19 对**。R6 旧摘要 `passing_parent_target_pairs=19` 只是“至少一景 PASS”；R6B 已在新目录修正。`532000→402005` 整对 HOLD。部分 PASS 仍有零票参考景；例如 `444000→384001` 的两张零票景均未在元数据声明目标，不能声称逐景无缺标。

## 物化链

- M1 首次写出在同一图中两个来源 ID 需归到同一目标 ID 时保护性停止，没有完整 manifest，不能使用。
- M2：独立复算 1,200 个 PNG、metadata、唯一 manifest 场景及 SHA 均一致；相对 V4 的 13,978 个变化像素恰在 24 个登记 action/22 场内，V3/V4/M2 前景逐像素相同。新 local 与原声明/v4 图内 ID 无冲突；可见 local/global 映射、bbox、面积和 train/val/test 身份隔离均正确。`Coord_003085` 两个来源合并到同一目标 local 61；`Coord_003139` 是同景两个不同目标，不是同目标合并。M2 但产生一个新生 1px GT，语义门失败。
- M3：独立全量重算确认相对 M2 **仅** `Coord_002894` 的 `(4,1)` 一个像素由新 local 38 变背景，其他 1,199 场 PNG/metadata 内容相同。24 个登记 action 中 23 个保留身份重赋（21 场、13,977 px），1 个仅删除 1 px；新增且保留的最小实例面积 133 px。1,200 场 SHA、元数据、bbox/面积、supervised split 身份隔离均通过；reader 未接入。

## 结论

**M3 文件/契约审计 PASS；语义发布门 FAIL。** `532000→402005` 一对、V4 excluded 的 6 场及相连误并仍未解决。R3 的 95 个形状风险 global 大量是合法屋顶条带/裁边，不能依据低填充率直接拆分，也不能把 95 当作所有相连误并的完备范围。因此 M3 是完整物化、可复核的第一轮候选，不是最终“一栋物理建筑一个实例”的可训练清洗版；不得切默认 reader 或以 AP 变化反调标签规则。
