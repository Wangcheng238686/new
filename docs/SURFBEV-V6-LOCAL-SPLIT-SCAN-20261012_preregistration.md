# V6：单图残余误并代码筛查（只读）

## 问题和范围

在用户确认 `003085` 的 M3 合并属于同栋之后，以 M3 1,200 场派生标签为只读输入，仅扫描 train/val 共 794 场。目标是发现一张图内同一 local ID 覆盖两栋楼的候选；不以跨场景 global ID 一致性作为训练标签语义门。本轮不改标签、元数据、reader、split 或模型，不读 test 图像来调筛选规则。visible-surface/roof-top 标签契约不变；形态学只作候选生成，不写回掩码。

## 固定候选规则

复用前轮 V3 诊断的 8 连通定义及阈值，以便直接对照，不事后调参：

- `M2`：同一 local ID 第二大 8 连通域面积 ≥64 px，且占总面积 ≥0.10。
- `strong`：第二大域面积 ≥128 px、占总面积 ≥0.20，且两大域最近间隙 ≥8 px。
- 相连候选只作探索性排序：原掩码必须恰好为一个 8 连通域、面积 ≥256 px、非裁边；圆盘开运算半径 2/4/6 px 后若出现两个面积各 ≥128 px 且各占原总面积 ≥0.15 的主体，记为“窄连接候选”。圆盘开运算不得用于修改标签。记录断颈位置及 RGB 梯度，保留原实例与 sham（同面积随机内部像素）的梯度对照；本门不把梯度当建筑真值。

## 输出、判读和停止门

主输出是 M3 的 train/val 残余 `M2/strong` 实例数、场景数与逐案例清单。伴随记录：连通块面积/占比/间隙、bbox 裁边、形态学窄颈候选数、候选/随机未命中固定抽样的 RGB 对照。旧 V3 的同一场景/局部 ID 仅作诊断引用：局部 ID 会重新编号，不能用 ID 集合差宣称多少实例已经修复。若需要真实修复数，另用掩码像素重叠建立旧、新实例映射。

统计为 794 场全集精确枚举，不作显著性或 AP 主张。固定选择残余 strong 中按第二块面积与间隙降序的最多 12 个不同场景，再按种子 20261012 均匀抽最多 12 个不同场景作反例；相连候选同样只看 train/val 固定代表，优先代码筛选，少量关键困难样本才请用户视觉判读，不调用视觉模型批量找。自动筛查仅 PASS/FAIL 数据契约与召回锚点，不作为标签发布门：来源 SHA/scene count/图像尺寸须全部一致，且已确认 `003085` 合并不能被当作待拆正例。若连通阈值主要筛出合法单栋屋顶，保留负结果并停止该规则，不能强行拆。

本轮属于数据侧冻结诊断，不启动训练、不申请 EXP-ID。首次定版后独立复核脚本、输入隔离、计数和可视化，再决定是否另立派生标签版本。

## 首轮实现审计后的代码修正

R1 代码没有显式检查窄颈候选的原始连通域数；独立审计复算表明 R1 产出的 25 条均恰好为一个 8 连通域，故已报候选未受影响。R2 仅补该显式检查、补预定随机未命中抽样，并删除可能被误读为“已修复数”的同 local ID 差集字段；阈值和输入范围均未修改。R1/R2 原样保留供追溯。

R2 独立审计指出，先对实例散列再去重场景并非场景均匀抽样。R3 改为先对场景固定散列排序，再在每个场景内固定散列选一个未命中实例；同时记录全部 train/val RGB 文件 SHA，便于审图复现。R1/R2 保留为审计过程，R3 是最终清单；主候选阈值、扫描范围不变。按 UE 全局 ID 检索重复图像曾命中远处重复资产，不能用于判定空间对应或物理楼栋，因此该支路废弃，不纳入 R3 结论。
