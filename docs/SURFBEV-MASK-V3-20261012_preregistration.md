# SURFBEV-MASK-V3-20261012：数据侧自动清洗预注册

## 背景与边界

用户明确要求规模化自动清洗，人工只进行**抽样可视化检查**；不逐例人工审完，
也不在模型损失或 COCO 评估中增加 `IGNORE`。本计划替代
`SURFBEV-MASK-QA-20261012_protocol.md` 中“全 113 例人工审完才清洗”的后续门，
但不回写或删除 R1 诊断。旧 v2 原始标签及 EXP-0006 保持不变。

这是数据版本构建/质量探针，不是 AP 实验。临时编号 `SURFBEV-MASK-V3-20261012`；
不启动训练、不打开模型预测、不用 AP 挑清洗阈值。任务监督仍为卫星可见建筑
表面投影，不外推到 ground footprint。

## 唯一自动变更规则

在原生 512² `satellite_instance_id_clean.png` 上逐 local ID 计算实际像素面积、
bbox 宽高以及是否碰图像四边。若且仅若

`touch_border AND (mask_area_px < 16 OR min(bbox_width,bbox_height) <= 2)`，

则在**派生 v3 PNG** 中把该 ID 的全部像素置为背景 0；其他像素逐位保持。
不写模型侧 ignore 标志、不修改 RGB/UAV/相机/原始 EXR/原始 PNG，不因一般触边、
多连通域、低填充率或模型预测结果自动删改。`instances.json` 保留原始 source，
派生 manifest 显式记载被剔除 ID；训练数据 reader 未来只根据 v3 raster 实际可见
ID 建立 mask/bbox。

这定义了“可评估建筑实例”的数据纳入门，并不宣称这些极小像素在物理世界不是建筑。
从 GT 移除后，模型若预测这些区域仍可能计 FP，这是数据任务定义的代价，必须在
后续 v3 B0 中如实报告。阈值来自 train/val 视觉检查；不因 test 分布或 AP 调整。

## 构建与审计门

输入只认 SHA `f15cd8…fe62a` 的 accepted-pair manifest 与 SHA `17f494…d5` 的
v2 split，逐场 1200 个来源 PNG 只读，派生 PNG/manifest 放新目录、拒绝覆盖。
脚本对所有分组应用同一规则；test 可以被确定性处理，但不抽 test 人工样本或用
其结果改规则。来源/派生 PNG 都逐文件 SHA256；每场变更 ID、删去像素数和分组
入 manifest。

**主门：** 1200/1200 场输出存在、可解码，派生与来源的逐像素差异恰等于被规则
选中的 local ID 全体像素；规则未命中的 ID 及像素严格保持。**伴随门：** 各 split
删除的实例/像素数、残余规则命中数（要求 0）、源文件 SHA、输出 ID 集合与
`instances.json` 映射、样本视觉检查。任何契约失败不放行 v3。

人工只做固定种子 20261012 的 train/val 抽样：每 split 从“有自动变更”的场景
选 12 个，从“无自动变更”的场景选 12 个，合计目标 48 个不同场景；若某层不足，
全部选并报告。为每例展示原图、v2/v3 叠加及 diff。抽样用于发现系统性错误，
不据此估计全量坏标率；发现完整可辨小楼被删除则规则失败，须另立 R2，不在
原输出上调阈值。首次实现需独立审计规则、原始数据不变、test 一致处理和哈希。

## 后续模型与指标

本轮不改 B0 reader 默认版本、不启动新训练。数据门通过后，另立 v3 B0 方案、
提交代码并按 EXP-ID/tag/全臂 harness/last 口径正式训练。v2 0.7952 val AP 与
v3 AP 因 GT 定义变化不可直接解释为模型提升；同时报告有效 GT 数、被剔除数、
segm/bbox AP 与面积分层。多连通域/多屋顶的物理实例归属另立 producer 规则审查，
不能在本轮按连通域自动拆分。
