# V6 图内误并：代码优先筛查结论（R3）

## 结论

R3 是可信的**只读候选清单**，不是自动拆分清单，也不是 M3 标签发布门。输入为 M3 1,200 场 manifest（SHA `3e36bd8a…3916e1261`），仅扫描 train 694 / val 100 场、40,784 个可见实例；test/excluded 不用于规则选择。没有修改 PNG、metadata、reader、split 或模型，没有 AP 结论。

| 自动规则 | 观测数 | 解释边界 |
| --- | ---: | --- |
| 第二大 8 连通域 ≥64 px 且 ≥10% | 58 | 其中 43 例触图边，不能把所有非连通都当多栋 |
| 上述中第二大域 ≥128 px、≥20%、间隙 ≥8 px | 28 | 其中 13 例触边；非触边 15 例集中在两个已知复杂屋顶审图组 |
| 原掩码单连通、形态学开运算形成两个大主体 | 25 | 只是形状候选；已看的代表例多为合法狭长屋顶/附属结构，不可自动切开 |
| 按场景均匀散列选未命中对照 | 12 场 | 审图盲区示例，不用于估计漏检率 |

按 UE 全局 ID 压缩重复相机观测后，28 个 strong 被归成 7 个**审图组**、25 个窄颈被归成 10 个审图组。这只用于减少重复查看，**不是物理建筑数**，更不能把全局 ID 当空间对应真值。曾试用同全局 ID 检索邻景，发现可返回远处重复资产，故废弃该支路；正式结论不使用它。

当前最需要少量人工判读的是触边案例，而非批量运行视觉模型。已生成 `002749`、`002739`、`003252` 的两大域双色图；它们的屋顶在画面边缘被截断，单图上不能稳妥断言一栋或两栋。`003019` 是高 RGB 梯度窄颈代表，但可见它的两个形态学主体仍可能属同一屋顶，证明“窄颈＋边缘强”不足以直接拆分。保留这些不确定结论，不凭分数改标签。
